# WHENMUSIC — 프로젝트 정의

> 재생은 남의 앱이 하고 이 앱은 그 위의 층이 된다. 형제 앱 [WHENWORK](https://github.com/when630/whenwork)·[WHENNOTE](https://github.com/when630/whennote)·[WHENCALENDAR](https://github.com/when630/whencalendar)·[WHENMAIL](https://github.com/when630/whenmail)과 같은 스택·구조·배포 방식을 쓰고, 역할만 나눈다. 요구사항 ID는 [02_요구사항.md](02_요구사항.md), 기술 결정은 [03_기술_스펙.md](03_기술_스펙.md). 2026-09-18 v0.1.

## What This Is

WHENMUSIC은 **재생 장치를 갖지 않는 음악 앱**이다. 소리는 Spotify가, 브라우저 유튜브가, 로컬 플레이어가 낸다. 이 앱은 Windows SMTC(System Media Transport Controls)에 붙어서 **무엇이 흐르는지 읽고, 탭을 찾지 않고 조작하고, 무엇을 들었는지 남긴다.**

화면 우하단에 작은 카드가 상주한다. 창을 여는 일은 드물다 — 이력을 뒤질 때만 필요하다.

## Core Value

**음악을 만지려고 창을 찾지 않는다. 좋은 곡이 지나갔을 때 그 자리에서 되감는다.**

기존 도구가 이걸 못 푸는 이유는 한 문장으로 요약된다 — **플레이어는 앱이고, 듣는 일은 층이다.**

- 음악은 Spotify 창이나 브라우저 탭 **안에** 갇혀 있는데, 듣는 행위는 작업하는 모든 앱 **위에** 걸쳐 있다. 그래서 조작하려면 매번 알트탭으로 그 앱을 찾아가야 한다
- 키보드 미디어 키가 그 간극을 메우려 하지만 **무엇이 재생 중인지 보여주지 못하고, 되감기 키가 아예 없다**
- 스트리밍으로 옮겨간 뒤 **내 청취 기록이 남의 서버에 있다.** Wrapped는 1년에 한 번 오고, 내가 원할 때 "지난주 그 믹스"를 찾을 수 없다

## 설계 원칙 — 형제 앱과의 대칭

| | WHENWORK | WHENCALENDAR | WHENMUSIC |
|---|---|---|---|
| 제1원칙 | **입력 비용 최소화** | **조회 비용 0** | **조작 비용 0** — 소리를 만지는 데 창 전환이 들지 않는다 |
| 주 UI | 창 | 상단 아일랜드 | **우하단 코너 카드** |
| 데이터 주인 | 내가 쓴다 | 남이 정한다 | **남의 앱이 만들고 이 앱이 관측한다** |

세 번째 줄이 이 앱의 특수성이다. 형제 앱은 모두 데이터의 발생지를 자기가 쥐고 있지만, WHENMUSIC은 **관측자**다. 그래서 얻을 수 있는 정보의 한계가 곧 제품의 한계가 되고, [실측](#실측이-바꾼-것)이 기획을 앞선다.

## 페르소나

| | 특성 | 도출되는 요구 |
|---|---|---|
| 주 사용자 | 한국어 사용, Windows 11. WHENWORK·WHENNOTE·WHENCALENDAR 사용자와 같은 사람 | 네 앱의 단축키·팔레트·화면 자리가 겹치지 않아야 함. 상단은 WHENCALENDAR가 쓰므로 **하단**으로 |
| 청취 형태 | **브라우저 유튜브로 1시간짜리 믹스 영상**을 듣는다. 로컬 음원은 거의 없고 스트리밍만 쓴다 (2026-09-18 확인) | 곡 단위 메타데이터가 **오지 않는다.** 기획 전체가 여기서 갈린다 |
| 상황 | 전체화면 IDE, 음악은 백그라운드 탭 | 전체화면 위에 떠야 함. 포커스를 뺏지 않아야 함. 클릭이 통과해야 함 |
| 불편 ① | 조작하려면 백그라운드 탭을 찾아가야 한다 | 카드에서 재생·정지·되감기가 끝나야 함 |
| 불편 ② | 좋은 곡이 나왔는데 뭔지 모르고 넘어간다 | **되감기**가 v1 필수. 도장은 되감을 여유조차 없을 때의 보조 |
| 불편 ③ | 뭘 얼마나 들었는지 기록이 없다 | 이력은 **믹스·채널 단위**. 곡 단위는 원리적으로 불가능 |

## 실측이 바꾼 것

2026-09-18, 사용자 PC에서 SMTC를 직접 찍은 결과가 기획을 두 번 뒤집었다. 전문은 [03 §실측 로그](03_기술_스펙.md#12-실측-로그).

| 처음 가정 | 실측 | 결과 |
|---|---|---|
| 곡 제목·아티스트가 온다 | **영상 제목과 채널명**이 온다 (`[𝐏𝐥𝐚𝐲𝐥𝐢𝐬𝐭] 우연히 듣고…` / `𝐂𝐡𝐞𝐫𝐫𝐲𝐌𝐢𝐱`) | 곡 식별을 **스코프에서 뺐다** |
| 앨범아트가 온다 | **PNG 150×83**, 16:9 영상 썸네일이고 곡과 무관한 채널 커버 | 아트를 정보 슬롯에서 빼 **배경으로** 내렸다 |
| 이력이 하루 수십 곡 쌓인다 | 1시간 영상 하나가 한 줄이라 **하루 3~4줄** | 이력을 **믹스 단위**로 다시 설계했다 |
| 재생 위치를 읽으면 된다 | 재생 중 갱신되지 않는다. 실측에서 **8분까지 낡아** 있었다 | 앱이 직접 **보간**한다 ([D-07](03_기술_스펙.md#d-07-position은-앱이-직접-보간한다)) |
| 미디어 키로 제어한다 | 대상을 겨눌 수 없고 **되감기 키가 없다** | 세션 직접 명령으로 바꿨다 ([D-04](03_기술_스펙.md#d-04-제어는-세션-직접-명령이다)) |
| 기존 애드온이 제어를 지원한다 | **읽기 전용**이었다 | MIT 라이선스라 **포크한다** ([D-05](03_기술_스펙.md#d-05-애드온을-포크해-제어를-더한다)) |

반대로 실측이 **가능하다고 증명한 것**이 이 앱을 성립시킨다 — 앱 id로 세션을 지목해 `TryPauseAsync`가 먹었고, `TryChangePlaybackPositionAsync`가 **오차 0으로 착지**했다. 되감기가 되기 때문에 "좋은 곡을 놓친다"를 풀 수 있다.

## 스코프

### 포함 (v1)

- **코너 카드 오버레이** — 우하단 상주. 무엇이 흐르는지, 어디쯤인지. 클릭 통과·포커스 없음·전체화면 위
- **탭을 찾지 않는 제어** — 재생·정지·이전·다음, 그리고 **10초 되감기**. 세션을 앱 id로 지목한다
- **구간 도장** — 단축키 한 번으로 지금 위치를 표시. 진행바에 눈금으로 남고, 눌러서 그 지점으로 되돌아간다
- **믹스 단위 이력** — 한 줄이 "한 번 들은 믹스". 채널·소요 시간·도장 개수. 초성 검색
- **도장 목록** — 확인 안 한 도장을 모아 되짚는다
- 내장 저장소 단일 파일, JSON 내보내기·가져오기
- Windows 설치 파일, GitHub Releases 미서명 배포, 자동 업데이트 알림

### 제외

| 기능 | 이유 |
|---|---|
| **곡 이름 식별** | SMTC가 챕터를 주지 않아 1시간 믹스 안의 곡을 알 길이 없다. 설명란 파싱은 videoId가 필요하고, 오디오 핑거프린팅은 API 키·유료·상시 네트워크라 "설치 파일 하나"에 어긋난다. **되감기가 이 필요를 대신한다** — 곡이 뭔지는 유튜브가 알려준다 |
| 자체 재생 (로컬 파일·스트림) | 재생 장치를 갖는 순간 이 앱은 층이 아니라 앱이 된다. 주 사용자에게 로컬 음원이 거의 없다 |
| Spotify·YouTube Music OAuth 연동 | Premium 전제 + 앱 심사·검증 비용. WHENCALENDAR가 같은 이유로 OAuth를 배제한 선례를 승계 |
| 라이브러리 관리 (태그·앨범아트 편집·파일 정리) | MusicBee의 일. 이 앱은 라이브러리를 갖지 않는다 |
| EQ·DSP·비트퍼펙트·고급 코덱 | AIMP·foobar2000의 일. 소리를 내지 않으므로 원리적으로도 할 수 없다 |
| 가사·추천·발견 | 몰입용 청취의 정답은 반복이고 발견은 그 반대다. 추천은 스트리밍 서비스가 이미 한다 |
| 생성 사운드스케이프·백색소음 | Endel·Brain.fm의 일. 취향이 없는 소리는 이 앱의 명사가 아니다 |
| 회의 자동 일시정지 | 기술적으로 가능하고(마이크 점유 레지스트리) 비용도 낮지만, **주 사용자가 겪는 불편이 아니다**(2026-09-18 확인). v2 후보 |
| 클라우드 동기화·계정 | 1인 1PC. 내보내기·가져오기가 이동을 대신한다 (형제 앱 동일) |
| macOS | SMTC가 Windows API다. macOS는 `MPNowPlayingInfoCenter`로 전부 다시 써야 한다 — v2 |

## 형제 앱과의 경계

| 앱 | 답하는 질문 | 핵심 명사 |
|---|---|---|
| WHENWORK | 뭘 해야 하지 · 뭐가 밀렸지 | 할 일 |
| WHENNOTE | 그때 뭐라고 적었더라 | 메모 |
| WHENCALENDAR | 다음 하나까지 몇 분 남았지 | 시각 |
| WHENMAIL | 이 사람한테 마지막으로 언제 연락했지 | 사람 |
| **WHENMUSIC** | **지금 뭐가 흐르지 · 방금 그거 좋았는데** | **소리 — 내가 만들지 않았고, 남의 앱이 내고 있다** |

음악은 시리즈에서 유일한 **출력**이다. 나머지 넷은 전부 입력·조회 앱이라 기능이 겹칠 위험이 구조적으로 낮다. 실제 접점은 둘뿐이다.

| 지점 | 처리 |
|---|---|
| 화면 자리 | WHENCALENDAR가 **상단 중앙**을 쓴다. WHENMUSIC은 **우하단**으로 고정한다 ([D-08](03_기술_스펙.md#d-08-카드는-우하단에-고정한다)) |
| 전역 단축키 | WHENWORK `Ctrl+Alt+Space`, WHENNOTE `Ctrl+Alt+M`·`N`, WHENCALENDAR `Ctrl+Alt+C`. WHENMUSIC은 `Ctrl+Alt+P`(창)·`Ctrl+Alt+S`(도장)·`Ctrl+Alt+←`(되감기) |

다섯 앱은 코드를 공유하지 않는다(모노레포·공용 패키지 없음). 검증된 모듈을 복사해 시작하고 각자 진화한다 — 초성 검색은 `whennote/main/search.mjs`를, 오버레이 창 기법은 `whencalendar/main/overlay.mjs`를 가져온다. 공유하는 것은 **스택·모듈 구조·디자인 토큰·빌드/릴리스 파이프라인·테스트 방식**이다.

## 완료 판정

작성자가 2주 사용한 뒤 **"음악을 조작하려고 브라우저 탭을 찾아간 횟수"가 0에 가깝고, "좋은 곡이 지나갔는데 그냥 넘긴 날"이 0일**이면 v1 완료.
